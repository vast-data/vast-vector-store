## What Went Well

### 1. Zero-debug stories (4 of 5)
Stories 2.1–2.4 completion notes all record *"no debugging required"*. This is a strong signal that story specs carried sufficient context and the architecture document's patterns (canonical imports, table access pattern, transaction pattern, hook signatures) were directly usable.

### 2. Architectural discipline held
- Single-file implementation constraint (`src/langchain_vastdb/vectorstores.py`) respected across all 5 stories.
- No helper modules created, no scope creep, no premature abstractions.
- Template Method hook architecture delivered as designed with 5 hooks at exact specified signatures.

### 3. Clean reviews
- 2 stories (2.4, 2.5) passed review with zero findings.
- Other 3 stories had exactly 1 deferred item each — no patches required, no decision-needed items, no rework iterations.

### 4. Cross-version CI green on first push
Python 3.10 through 3.13 all green on the first CI run for every story. Type hints with `from __future__ import annotations` and PEP 604 union syntax worked uniformly.

### 5. Security requirements met without ceremony
Credentials (`access_key`, `secret_key`) never stored as instance attributes; verified by unit tests.

## Challenges & Struggles

### 1. Pydantic frozen-model patching (Story 2.5)
**What happened:** Two tests (`test_add_texts_embeds_via_embed_documents`, `test_similarity_search_by_vector_skips_embed_query`) initially failed because `DeterministicFakeEmbedding` is a frozen Pydantic model — instance-level `patch.object` raises on attribute assignment.

**Resolution:** Patch at class level (`patch.object(DeterministicFakeEmbedding, "embed_documents")`).

**Severity:** Minor (single-session fix, no rework of production code).

### 2. Mocked unit tests can't validate three real-world concerns
All three deferred review findings share a root cause: **mocks cannot exercise SDK type coercion, null handling, or concurrency semantics**. Epic 3's integration test suite is the natural place to validate them.

## Key Insights

1. **Planning paid off.** The architecture document and per-story specs were detailed enough that 4/5 stories completed in a single pass. The review-loop iteration count was 1 across the board. Invest in story specs early — it prints velocity later.

2. **Mocks have a ceiling.** The three deferred items all fall in a zone mocks can't reach. Accepting that ceiling and routing findings to integration tests is correct; trying to simulate SDK behavior in unit tests would have been wasted effort.

3. **Model switch was a non-event.** Opus 4.6 handled 2.1–2.3, Sonnet 4.6 handled 2.4–2.5. Both produced clean reviews. No quality delta observed. Sonnet is viable for stories of this complexity when specs are detailed.

4. **First-retrospective baseline.** No prior retro existed to cross-reference. This retro establishes the baseline; Epic 3's retro will be the first one with follow-through tracking.
